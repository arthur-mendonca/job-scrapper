Create a backend-only TypeScript/Node.js job intelligence pipeline for personal use.

Goal:
Automate the discovery of international remote software engineering opportunities without requiring me to manually search job boards every day.

The app should collect jobs and hiring posts from multiple sources, normalize them, deduplicate them, score them against my profile, store them in a PostgreSQL database, and notify me through Telegram and optionally email.

The app will be hosted on my own VPS and must run inside Docker containers using Docker Compose.

Important constraints:
- Do not use NestJS for the MVP.
- Do not build a frontend for the MVP.
- Do not use GitHub Actions as the scheduler.
- The app must run as a Dockerized background worker on a VPS.
- The app must support scheduled execution using an internal scheduler, such as node-cron, or a container-safe cron strategy.
- Do not implement authenticated LinkedIn scraping, cookie-based scraping, CAPTCHA bypass, stealth browsing, or automation that logs into LinkedIn.
- LinkedIn-related discovery should be limited to public search results, search-engine-indexed posts, manually provided URLs, or parsing job alert emails.
- The system should be modular so that new collectors can be added later.

My target profile:
- Backend-leaning Full Stack Software Engineer
- Main stack: TypeScript, Node.js, NestJS, React/Next.js
- Additional skills: AWS, Docker, CI/CD, PostgreSQL, AI/LLM automation
- Target roles: Mid-level / Intermediate Full Stack Engineer, Node.js Developer, Backend-leaning Full Stack Engineer, AI Automation Engineer
- Preferred market: remote international roles, LATAM-friendly, USD compensation
- Avoid roles requiring 7+ years, staff/principal-only roles, onsite/hybrid roles, US-only roles, or roles where Python/Java/.NET/PHP are the primary stack

Data sources:

1. SearXNG collector:
   - Query a self-hosted or externally hosted SearXNG instance using its HTTP Search API.
   - Use search queries for remote TypeScript, Node.js, NestJS, React/Next.js, AWS, Docker, LATAM, contract, and USD jobs.
   - Search for both formal job pages and hiring posts.
   - SearXNG base URL must be configurable through environment variables.

2. ATS collectors:
   - Add collectors for public Greenhouse, Lever, Ashby, and Workable pages.
   - Allow a configurable list of company career pages.
   - The app should support a config file such as `config/companies.yml` or `config/sources.json`.

3. Job board collectors:
   - Remote OK
   - We Work Remotely
   - Remotive
   - Himalayas or similar sources where accessible

4. Email/job alert collector:
   - Allow parsing raw job alert emails or email-exported HTML/text files.
   - Extract job title, company, URL, location, and description when available.
   - For the MVP, this can work by reading files from a mounted local folder such as `/app/input/email-alerts`.

Core modules:

1. collectors/
   - Define a JobCollector interface.
   - Implement collectors for SearXNG, ATS pages, job boards, and email alerts.
   - Each collector should return raw job-like items in a common format.
   - Collectors should not write directly to the database.

2. normalizer/
   - Normalize title, company, location, seniority, remote type, salary, stack tags, source URL, and canonical URL.
   - Detect stack tags from title, description, and requirements.
   - Detect seniority from title and description.
   - Detect remote compatibility and location restrictions.

3. scoring/
   - Score each job from 0 to 100.
   - Return score, match reasons, risk flags, and recommended action.
   - Positive signals:
     - TypeScript
     - Node.js
     - NestJS
     - React
     - Next.js
     - AWS
     - Docker
     - CI/CD
     - PostgreSQL
     - REST APIs
     - AI/LLM
     - remote
     - LATAM-friendly
     - USD
     - contract
   - Negative signals:
     - 7+ years required
     - staff/principal-only
     - onsite/hybrid
     - US-only
     - vague company
     - unpaid test project
     - primary Python/Java/.NET/PHP requirement
     - unclear compensation
     - generic job description

4. deduplication/
   - Deduplicate by:
     - canonical URL
     - normalized title + company
     - content hash
   - Avoid notifying the same job more than once.
   - If an existing job is found again, update `updatedAt` and optionally create a JobEvent.

5. persistence/
   - Use Prisma repositories for jobs, companies, recruiters, and job events.
   - Keep database operations separate from collectors.

6. notifier/
   - Telegram notifications for jobs above a configurable score threshold.
   - Optional email digest.
   - Do not notify jobs already notified.
   - Add a daily or per-run summary notification.

7. scheduler/
   - Implement a worker that runs collection periodically.
   - Use an environment variable such as `COLLECT_CRON`.
   - Example: `COLLECT_CRON=0 */6 * * 1-5` to run every 6 hours on weekdays.
   - Also support manual one-shot execution.

8. cli/
   - collect command
   - worker command
   - report command
   - test-query command for SearXNG queries
